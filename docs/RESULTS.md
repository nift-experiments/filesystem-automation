## Interpretation boundaries

Fresh includes launch/exit; booted starts after readiness and finishes on a complete serialized response. Every official request gets a new runtime. Lifetime CPU/RSS include startup even for booted requests. wait4 RSS also includes the pre-exec supervisor-image floor; it is not exclusive runtime memory. Exact outputs and independently reconstructed reset manifests pass. All samples remain retained; p95 is nearest-rank and equals the maximum below 20 samples.

Read includes a full-byte in-language portable checksum; native SHA-256 is separate and unavailable in Nift. Large reads use a full read plus endpoint aggregate, with full SHA-256 fixture checks outside timing. Write/overwrite/large-write include source reads. Copy checks bytes/path rather than preserved metadata. Delete leaves directories. Hash change detection uses a noncryptographic recurrence, not a security guarantee.

The primary basename filters test 1/10/50% selection; the separately frozen extension/prefix/size supplement selects 20/5/40%. Mtime and content change detection have intentionally different semantics. Mixed work ignores group19 before reads, generates .md, copies .dat and writes a manifest; traversal still visits ignored paths.

Derived input-files/sec and source-MiB/sec appear in each cohort’s derived-throughput.json, with operation-specific qualifications. These are not device bandwidth measurements.
