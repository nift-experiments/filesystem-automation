# Frozen primary-cohort method

Project-tree automation on warm Linux filesystem state, not physical disk speed. Same deterministic fixtures, native in-language operations, no external find/copy/hash helpers. Sequential operations; filesystem concurrency is omitted because the separate campaign already covers it.

## Boundaries

Fresh: runtime launch, BOOT, request, complete JSON result, EOF and exit. Booted isolated request: new runtime reaches BOOT outside the clock; the request and complete response are timed, teardown outside. Native code compilation and fixtures are outside both. An independent repeated-runtime diagnostic will check whether retained runtime state changes behavior; isolated booted measurements must not be presented as reused-runtime throughput.

Participant result serialization is inside timing for everyone. Each adapter returns the exact path/size/value rows; the supervisor canonicalizes and checks them outside timing. Destructive state preparation and full SHA-256 destination verification are outside timing. Per-process wait4 CPU/RSS are lifetime metrics, including startup even in booted rows; wall-time is the primary comparable boundary.

## Fixtures and scope

Canonical trees: 1,000, 10,000, 100,000 files; ASCII project paths, three nested levels, five extensions, deterministic 96/192/384/768/2048-byte ASCII content. Fixed integer-second mtime. Exact SHA-256/size/mtime manifests retained. Independent oracle reconstructs counts/path sets and all generated bytes. No symlink or permission benchmark is implied; separate semantic probes cover edge paths/errors.

Large fixture contrast: 10×10MiB and 100×1MiB. Large reads verify byte count plus deterministic endpoint aggregate; full fixture SHA-256 is checked outside timing. Large stream writes include source reads. No fsync/device-bandwidth claim.

All principal operations run at 1k/10k. Traversal, stat, filter, read/checksum, SHA-256 and copy additionally run at 100k. This bounds repeated expensive mutation/hash workloads. Optional glob API parity, path microbenchmarks, 250k/1m stress and additional concurrency are omitted.

## Implementation contracts

Nift ls sorts directory names and requires separate is_dir inspection. Python uses os.walk; JS uses Dirent readdirSync; Go uses WalkDir (sorted directory entries). Native API differences remain explicit; no artificial extra sorting/stat calls are added to peers. Result rows are canonicalized outside the clock. Canonical manifests must be sorted inside each measured manifest operation.

Read/checksum uses the same noncryptographic recurrence h=(31h+byte)%1000000007 in-language over every byte. It is one workload, not duplicated as another hashing result. SHA-256 is a separate native-library workload for peers; Nift has no located public SHA-256 API and is marked unavailable rather than supplied an FFI shortcut. The noncryptographic recurrence is not a security digest or general collision-free change detector. Full independent SHA-256 output verification protects correctness for this controlled corpus.

Stat contract: regular-file size/type, not mtime. Nift stat exposes no mtime in this snapshot, so timestamp detection cells are unavailable. Others compare integer-second mtimes. Detection mutations use the same 1% set: changed bytes/newer time; identical bytes/newer time; changed bytes/restored time. These provide distinct guarantees.

Primary filter cases select deterministic filename-id residues (1/10/50%). All five extensions, group directories and sizes≥96 are fixture invariants, not independently tested predicates. A separately frozen supplement tests .md extension, group00/ prefix and size≥768 at each tree size. These cohorts retain distinct suite identities and observations. Mirror uses content recurrence equality, preserves identical files, copies changes/additions and removes unexpected files. Profiles: clean, 1% content, 10% content, 10% content plus 1% added/deleted, and 1% added/deleted only. Copy correctness is paths/bytes, not permissions/mtime preservation. Stream write/overwrite include reading source bytes. Delete removes all files, leaving directories: Nift public remove rejects directories; recursive directory deletion is not falsely presented as equivalent. Rename batches traverse source paths; relocation renames top-level group directories within one filesystem.

Generated pipeline reads/checksums source and writes generated-prefix content plus a sorted TSV manifest. Mixed workflow ignores group19, selects .md/.dat, generates .md outputs, copies .dat assets unchanged and writes a manifest. Selection is applied before reads, but traversal itself still visits ignored paths. The controlled transform is intentionally light; this is not a site build.

## Lifecycle

Every destructive sample restores outside timing, records a starting-state SHA-256, warms source/destination by full reads/stat, measures, and verifies the exact final state. Participant order rotates within rounds; warmups remain separate; all samples retained. No global cache dropping. Sample counts are frozen after local feasibility and common across participants per scenario.

Frozen plan: 68 scenarios, 662 supported boundary/runtime cells, 12074 measured observations and 662 separate warmups. Local projected timed work is 9,371 seconds, excluding fixture preparation/verification and cloud-machine differences. Stress distributions with three samples are descriptive; nearest-rank p95 equals maximum for fewer than 20 samples.
